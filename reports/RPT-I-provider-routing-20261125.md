## Existing integration facts (not compliance claims)

* `model_registry.py` has Gemini role pins, but `assert_model_permitted()` blocks only forbidden IDs, not unregistered IDs; `Config.model_for_role()` accepts configuration. The registry alone is not the required runtime personality pin.

They escalate on verification, not the specified 429 tier transition; audit both plus their transports and cancellation/retry handling. `daemon.py` calls the client directly (`_generate`), and Live/transcription/tts have separate paths. This is a real transition in behaviour, not a claim already satisfied. Verify the owner-selected local voice and explicit precedence of the newer ruling before changing audible identity; hardware acceptance needed. `asr.py` has optional local faster-whisper, but installation/model and true all-cloud-down operation are not established by presence of code.

Adding empty or zero provider rows under `quota.models` would misstate verification or limits; it would not enforce per-provider budgets. Calls in other transports require audit, not just a new adapter.

## 2. Proposed seam and budget (design, not code)

At a single privileged dispatcher below all callers, distinguish closed enums `PERSONALITY`, `MATERIAL`, and local deterministic status. Unknown purposes fail closed; caller cannot claim arbitrary model/provider or promote material to spoken output. Personality selects only compiled-in Gemini transport and registry `CHAT_INTENT`/`ESCALATION` exact IDs, never a configurable URL, fallback provider, proxy or arbitrary adapter. Explicit code-owned host/transport allowlist matters as much as model string; deny redirects to unknown hosts. Direct Live speech and cached cloud TTS must be removed/disabled or separately contained when implementing the new spec, otherwise the seam is bypassable. Enumerate all call sites and enforce at the actual network boundary; test synchronous, async, streaming, Live and TTS, including direct invocation.

Material adapters receive only authorized minimized data and return opaque, untrusted material tagged with source, model and provenance, not an owner-facing reply. The only presentation conversion accepts a successful Gemini personality result, with material passed in a clearly delimited untrusted data channel and treated under IF-6; no instructions/actions from it. Never concatenate raw material into final text, stream it to TTS/UI, or use it on timeout. Prompting alone cannot prove semantic paraphrase or prevent a model quoting text; require structural non-passthrough and test with distinctive canaries, and recognize that a model may independently reproduce material. Display of raw source as explicitly labelled source data, if ever desired, is a separate consent/product decision.

Ladder: normally lite; flash only explicit verification-driven escalation with budget available. Flash 429/exhaustion => lite, not another provider; lite unavailable => fixed short local budget notice, no foreign/generated personality fallback. Material may still be handled by a separately eligible provider, not automatically spun through providers to extract more quota. All cloud unavailable => local operations only, with explicit text/speech availability and no state deletion. Retry-after and reset tracked per provider/model/window; transient errors use bounded cooldown and probes, never wait indefinitely, recovery automatic without erasing memory. Do not assert local reminders/wake/lock/transcription work until end-to-end tested with dependencies installed.

**Budget declaration:** no new feature calls authorized in this report: Gemini lite 0 new/day, flash 0 new/day, diverted 0/day; stranger/feed per-source 0/day; hard cap 0 until reviewed. Existing budget remains owner's `[quota]` (lite 500 RPD with 400 config cap; flash 20 RPD escalation-only, source/date in `config.toml.example`), shared with all existing features, not additional allowances. A future feature must declare its estimated volume, per-source ceiling and reserved headroom; atomically reserve requests and token/compute budget before dispatch. Never rely on shadow pricing or a limiter as a guarantee of $0: require confirmed free-only account/endpoint, supported hard stop, every model and every billed dimension at zero, fail closed on unknown pricing/plan. If not demonstrable, defer.

**Quota row design:** separate `[quota.providers.<provider>]` with enabled=false by default, account-verified date/source, plan, model-specific rows, scope/window/reset, distinct units (requests/tokens/neurons), and *positive* caps; absent/unknown means unavailable, not unlimited. Use `None` for unknown and explicit unlimited only for evidence-backed limits, never 0. Provider rows must not inherit Gemini's global verified marker; implement schema validation, doctor and consumer independently, with migration tests. No entries in runnable config until owner-account verified; no invented credentials. Enforce caps across processes and restarts with transactional reservations; include failed attempts, estimated reservations and provider reconciliation. Do not silently reset on restart or substitute the Gemini global day for another provider's window.

**Ledger design:** migrate `llm_calls` with explicit provider, model, purpose, attempt, timestamps, request ID, mode, status, token counts (nullable if unavailable, not zero), provider-reported actual cost (nullable unknown), and evidence of free plan; report daily totals grouped by provider and separately flag unknown cost/tokens. Backfill historical rows only where provenance is provable; mark others unknown. Journal an attempt/reservation before a network send, terminal result or unknown on cancellation/crash, including retries and 429s. Ledger write failure refuses new cloud calls. Ensure text, credentials and raw prompts never enter ledger. Audit direct Gemini Live, speech, transcription and SDK retry calls: hidden SDK retries defeat one-row-per-call unless disabled or instrumented. A numeric shadow estimate is not actual billing.

## 3–8. Pre-build review and adversarial test plan

These are **design reviews and proposed tests**, not executed tests of a new implementation. They identify blocking issues rather than certify the gate.

3. **Scale stress:** concurrent requests and restarts can overspend a quota if check/increment is separate; require transactional reservations and bounded queues. Large untrusted material can consume context/tokens: bound bytes, tokens, duration and concurrency; keep wake/lock independent of queue/backpressure. Cold mic and stranger voice require owner-hardware and identity tests, not simulations alone.
4. **Fact-check:** current config defaults and TTS differ from target (above); documented 429 holds do not prove the requested degradation. Free-plan descriptions and accounts can diverge; authoritative account evidence is required, and GitHub Models is retired. Cloudflare neurons and Cohere monthly calls do not fit current RPD model.
5. **Research gaps:** no actual local hardware profile, model/weights selection, owner plan screenshots or terms acceptance; Mistral docs conflict; no exact plan-specific no-card and legal/privacy confirmation for each candidate. Voice identity transition and available local voice need owner decision and ear check. No provider should be enabled pending these.
6. **Adversarial design checks:** malformed/unknown task or model, provider names in config, proxy URLs and redirects, 429/503, retries, cancellation, parallel reservation, clock rollback, restart, partial streams, missing usage, ledger failure, untrusted material saying 'ignore instructions', source impersonation and malicious URLs, material pasted as final, fake successful re-voice, offline wake/lock, stranger voice and consent bypass. Expected: refuse or clearly label fixed local status; no untrusted data is authority; no paid call, secret leak, unauthorized action, or other-provider personality.
7. **Second stress review:** 429 storms must not trigger provider fan-out; one bounded attempt per admitted work item and circuit breaker with jitter. Enforce per-source caps atomically, keep separate material and owner reply deadlines, avoid starvation and retain durable memory. A fixed notice can be spoken only if approved local voice available; otherwise labelled text, not a fabricated success.
8. **Final author/enemy review:** the critical attack is bypassing dispatcher via existing direct SDK/Live/tts paths, or using a free-labelled adapter with a paid model. Require static call-site census and network-boundary integration tests; prove target enforced across actual IPC/UI/audio sinks. Explicitly review false local availability and missing ledger rows. These checks are not yet executed against an implementation, and the manager must review this report and outstanding facts before build.
