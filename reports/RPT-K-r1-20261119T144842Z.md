## G. NEGATIVES & CORRECTIONS

1. **BASELINE BUG FOUND AND FIXED ON RECORD** — `notify()` could **spin forever**: `while (el.toasts.children.length >= 3) closeToast(el.toasts.firstChild);` but `closeToast()` only adds `.out` and removes the node 450 ms later, so the loop condition could never become false. A **fourth notification inside one tick froze the shell** (found by the new test; it hung the suite at 300 s). Fixed by dismissing the oldest **non-fading** toast and hard-dropping one if all three are already fading; `closeToast` is now idempotent (`_orbDone`). Regression asserted: 5 notifications in one tick return in **< 500 ms** (measured 0-1 ms), **<= 3** slots held, newest survives. This bug predates this round and existed at `6fab0d0`.
2. **Empty injection result fails to discriminate** — "no element was created" alone would also hold if the card never rendered. The test therefore **also** asserts the snippet text is present in full (1 text node, exact string) and that an HTML-smuggling **recipient** renders literally, so inertness is proven against a positive control. The `innerHTML`-in-draft-block guard was validated the same way: clean block -> no match, block with an injected `innerHTML` -> match.
3. **"draft round-trip passes" fails to discriminate against an optimistic UI** — a card that flips itself to `sent` on click would also "pass". Three fail-closed tests exist to separate them: a **silent** daemon (`{}`) leaves the card **pending**; a daemon with **no transport** leaves it pending and says nothing was sent; a **throwing** refusal leaves it pending with the refusal shown verbatim.
4. **Sizing doctrine is only proven statically here.** No Chromium/playwright-core in this sandbox, so `layout-test.js`'s live pixel gate did **not** run: the 36%/80% geometry, footer bounds and no-crop claims rest on the CSS numbers and the static gate, **not** on measured pixels at 1920/1440/1024/800/390/320.
