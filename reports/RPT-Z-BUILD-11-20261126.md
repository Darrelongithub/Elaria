## Implemented surface

- `discovery.Policy`, deterministic metadata filtering/ranking, configured roots,
  bounded walks, vendor/hidden/symlink/protected exclusion, ZIP/TAR manifests,
  traversal/link/device rejection, archive expansion/member caps, no extraction.
- `streamread.inspect`, `read_batch`, `read_window`, opaque continuation cursors,
  JSON container records, JSONL, CSV/TSV (including multiline rows), local SQLite,
  office/text readers; explicit unsupported-PDF error rather than empty success.
- `assist find`, `inspect`, `read --all`, `stream-report`; owner IPC `fs.locate`,
  `file.inspect`, `file.read`.
- Configured stream/discovery limits, example parity, Store schema migration,
  extraction provenance fields, metadata queries and paginated stored chunks.
- Errand chain: discover → inspect structured files → bounded record-aligned
  `file.read` → analyze → inferred memory → owner clarification → report.
  Plain prose retains bounded byte windows. Archive containers are not read as
  prose; their selected members are separate targets. Errand discovery ranks all
  eligible files, whereas explicit find defaults to term matching.
- Reads carry `trusted=False`; never-send files are excluded before cloud analysis.
  Read journaling carries provenance, not content. Untrusted text cannot directly
  create stated memory; owner confirmation remains the authority transition.
- Partial reads and failed inspections are named in reports. Record text rendering
  caps are surfaced as truncation/notes, even when the underlying stream reached
  EOF. `read_batch` retains full record values. Bounded iterators raise when their
  batch limit prevents reaching EOF; oversized line records fail instead of looping.

## Blueprint, reuse, limits and budget

Reuse the repository's protected-path, owner-auth IPC, SafetyJournal, Store and
errand model dispatcher rather than adding a parallel authority path. Use Python
stdlib `json.JSONDecoder.raw_decode`, csv, zipfile, tarfile and read-only sqlite3;
no new runtime dependency or copied third-party source. These are PSF-licensed
Python standard-library facilities. The source audit's ijson alternative was not
installed. No paid search, external account, or hosted parsing service.

[quota]
- Discovery, schema inspection, streaming and extraction reporting: **0 model
  calls/day, 0 model tokens, hard cap 0**. No per-stranger reply surface.
- Errand content analysis uses the existing dispatcher/workhorse tier and owner
  quota enforcement; defaults remain max_api_calls=10 per errand and
  max_step_api_calls=2. No new flash escalation calls. Tests use mock responses.
- No claim of a newly verified live provider quota; the owner-verified table and
  existing dispatcher remain authoritative.

Budgets are deliberate: 50,000 walked entries, depth 32, archive member bounds,
64 KiB stream windows / 200 records by default, per-file cap 8 MiB. A structured
JSON record can exceed a nominal window to preserve its boundary, subject to a
4 MiB record guard. CSV/JSONL rows bigger than a window require an increased
byte budget and fail loudly. A 12-step errand may report a partial file; the
large-file lifecycle test explicitly grants 32 steps for inspection plus nine
record windows. It still checks the late conflict beyond 200 KiB and EOF.
