### BUG-B1 · P0 · `src/assistant/hands/gate.py:148-159, 182-190, 198-211` · `GateChecker.derive()` misclassifies forbidden tier-3 `exec` commands, sandbox-escaping `argv[0]` paths, relative shebang scripts, and `curl` exfiltration flags as tier 2

- **Failure mode:** Multiple independent holes in `GateChecker` allow tier-3 (`forbidden`) actions and protected/control-plane paths to pass `derive()` as tier 2 (`ask=True`, executable on `"yes"` and entered into `Reporter.plans` / `disclosures`):
  1. **`argv[0]` skipped in `paths()` (`gate.py:150`):** `args = step.argv if step.tool != "exec" else step.argv[1:]` omits `step.argv[0]` from `path_allowed()`.   3. **Wrapper-launched shells/interpreters & `rm --recursive=always` (`gate.py:182-186, 201-204`):** `derive()` inspects only `step.argv[0]` against `SHELLS | EVAL_BINARIES | INTERPRETERS` (missing `timeout`, `nice`, `nohup`, `stdbuf`, `setsid`, `pkexec`, `systemd-run`) and checks `a == "--recursive"` by exact equality (missing GNU `rm --recursive=always`). ### BUG-B3 · P0 · `src/assistant/hands/headless/worker.py:41-60, 98-133` + `tests/test_hands_headless_host.py:108-125` + `tests/test_hands_headless_worker.py:88-100` · `Worker.execute()` tracks subprocesses only *after* exit, leaving live workers unsignalled on daemon death while `terminate_all()` `killpg`s dead/recycled PIDs (masked by tests)

- **Failure mode:** `default_runner()` (`worker.py:41-60`) spawns `subprocess.Popen(..., start_new_session=True)` and blocks in `proc.communicate(timeout=60)` until the child exits before returning `RunnerResult(..., process=proc)`. `Worker.execute()` (`worker.py:99-102`) only appends `proc` to `self._live` *after* `self._runner(...)` returns:

  2. **PID-reuse `SIGTERM` hazard & `Popen` leak (I10):** Every finished process is appended to `self._live` *after* it has already exited and is never pruned until `terminate_all()`. Note also that once `proc.communicate()` has reaped the child, the OS is free to recycle `proc.pid`; `proc.poll()` still returns the cached exit code (`0`, so `if proc.poll() is not None: continue` happens to skip cleanly-exited `Popen` instances), while leaking every completed `Popen` object in `self._live` across the host's lifetime (violating I10) and leaving any timed-out/unreaped path unguarded while running.
  3. **Safety-net test defect:** Both `test_daemon_death_terminates_workers_and_journals` (`tests/test_hands_headless_host.py:113`) and `test_terminate_all_signals_tracked_process_groups` (`tests/test_hands_headless_worker.py:91`) manually execute `worker._live.append(proc)` instead of running `worker.execute()`, making the tests unable to detect that `execute()` never populates `_live` while the child is alive.
- **Evidence (SANDBOX, threaded `Worker.execute` with a `sleep 0.4` pinned fake kitty):**
  - Calling `worker.terminate_all()` at `t = 0.12s` while `w.execute(RemoteRequest(verb="ls"))` is running returns `signalled = 0` (child continues running to completion).
  - After `execute()` returns: `len(w._live) == 1` and `w._live[0].poll() == 0` (dead `Popen` retained in `_live`).
- **Suggested owner:** `P` (`src/assistant/hands/headless/worker.py`, `tests/test_hands_headless_{host,worker}.py`).
