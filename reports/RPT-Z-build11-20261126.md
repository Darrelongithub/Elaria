# BUILD-11 — discovery and bounded streaming

## Delivered

- Owner-configured discovery roots are separate from organiser roots. Discovery uses no-follow, descriptor-relative directory traversal; protected, ignored, hidden, symlink and build trees are pruned. Filename/path/metadata search includes non-text filenames and ZIP/TAR manifests without extracting archives. Manifest limits, unsafe names and errors are surfaced. Errand steps cannot enlarge their authorized root scope.
- Byte-window reads preserve UTF-8 boundaries, carry untrusted provenance, and detect source changes. Local files and archives are opened via no-follow descriptor traversal. Archive expansion and members are bounded. Indexed text is returned by a cursor-based API rather than a 600-character preview; `never_send` is refused at the cloud-bound chunk/read-batch seams.
- `structured_reader` pages and validates JSON arrays and objects, JSONL, CSV/TSV (including multiline records), HTML, SQLite, PDF, OOXML and readable ZIP/TAR members. Cursors bind to source hashes; failures and budget stops are explicit. SQLite is copied in bounded chunks to a private, temporary, read-only snapshot, with WAL-mode and virtual tables refused. The errand runner performs structured inspection, validates fully-read JSON/CSV through EOF, drops invalid content from analysis, and pages SQLite/PDF/OOXML with the read-only `file.read_batch` skill. It records schema/type counts rather than treating extracted records as instructions or verified factual evidence. Safety journal entries contain provenance and counts, not record contents.
- Plain text, PDF and supported OOXML text are streamed into transactional index chunks; no silent 200 KB cutoff. Corrupt or over-limit extractions are errors and stale content is excluded from indexed retrieval. Existing indexes migrate and re-extract once. OOXML reads XML incrementally with DTDs refused, ZIP expansion bounds, and includes spreadsheet text and worksheet values.
- Verification exercises two fixture domains (botany and workshop), >200 KB minified JSON, large OOXML and SQLite, ZIP/TAR manifests, multiline CSV, UTF-8 boundaries, injection text as data, protected paths/symlink swaps, change detection, rollback, stale-index suppression and end-to-end SQLite errand batching.

## Explicit limits and follow-up

- Hard per-record, archive-expansion, SQLite snapshot (1 GB), PDF conversion time, and errand-step bounds fail or pause loudly rather than silently truncate. A huge individual nested JSON value above the record limit is refused rather than token-streamed. WAL-mode SQLite must first be checkpointed into a rollback-mode copy; virtual tables and nested PDF/OOXML inside archives are not interpreted. Snapshotting uses a private temporary file that is cleaned up on normal exit; abrupt process termination can leave temporary data behind.
- PDF requires `pdftotext`; images do not receive OCR. OOXML extraction streams textual values and spreadsheet worksheet values, not complete visual layout, formulas or resolved shared-string relationships. Direct `extract_text` remains an explicitly bounded preview API; full text lives in streaming reader/index chunks.
- SQLite/PDF/OOXML structured pages currently contribute local schema/type counts, not semantic claims: record contents are not automatically promoted to memory. Corpus-wide semantic map/reduce and the pre-existing broader memory-recall cloud/privacy path are separate follow-up lanes. A budget-paused file is explicitly incomplete. Archive and record pagination replays earlier content and may be slow on large inputs.
