## The original NUS

**potlakai/nus-companion** (the other hit, geohot0199/NUS, is the
same product family) — *"Ask about your screen by voice or text.
The Knot points, guides and can act."* Hold a hotkey, ask about
what you see; it answers, **points at the right place**, walks you
step by step, or acts with "Hands". Its marks (underlines, rings)
land only on elements the OS accessibility layer can find —
grounding is accessibility-first, not raw VLM coordinates.

## Grounding model (screenshot → coordinates, the fallback)

**bytedance/UI-TARS-desktop** (Apache-2.0) + UI-TARS-1.5-7B model:
screenshot + instruction → click coordinates/actions; also
NeuralAction (Apache-2.0, 4B, 0–1000 normalised coords) and
ScreenSpot-Pro (MIT, benchmark). Licence-clean. Use for elements
AT-SPI cannot see (canvas, images, games) — never as first choice,
because a coordinate with no element identity behind it cannot be
stated in a consent plan.

## The architecture this implies (blueprint seed, agents deepen)

1. **Ask** (voice, her existing wake path) → screenshot via portal
   (consent posture per IF-6: screen content UNTRUSTED, what
   leaves the machine is a policy decision, not a default).
2. **Ground**: AT-SPI element tree first (identity → can be named
   in a plan → can be circled precisely); VLM coordinates only as
   fallback, labelled as unidentified.
3. **Point**: her orb + ring on the layer-shell overlay at the
   element's real bounds (`nus/shell.qml` grows this; the draw
   itself is a solved problem — multiple Hyprland circle overlays
   exist, e.g. m39d/crosshair-overlay).
4. **Act** (only via hands gate, digest-bound owner-yes, tier-3):
   computer-use-linux mechanism, screenshot-after verification.
