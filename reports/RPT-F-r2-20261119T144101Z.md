## F. ASSUMPTIONS

**F.1 — Ask 43 was built rather than filed as `Z`-only.**
DECISION-TABLE routes ask 43 as "Z / F · identity/readback". Identity **readback**
is a reader — F's own category — so it is built here. Nothing in it requires
editing `daemon.py`: it reads `status` over the existing IPC client. HR-F-6 asks
Z only for the convenience field, not for the capability.

**F.2 — `stale_checkout` outranks `dirty_checkout`.**
A stale daemon is a correctness problem (your test result is about code that is
not running); a dirty tree is an imprecision (which sha is "the" sha). When both
are true the verdict says `stale_checkout`, because that is the one that invalidates
the evidence. `different_checkout` outranks both — the daemon is running a
*different tree entirely*, which is a stronger claim than either.

**F.3 — The pid is proved by socket inode, never by process name.**
Matching `assistant.daemon` by name would be wrong the moment two daemons run
under different `XDG_RUNTIME_DIR`s — which is exactly the situation ask 43 is
about. Verified live: `/proc/net/unix` inode `10849` → `/proc/3305/fd/13 ->
socket:[10849]` → `daemon_pid 3305`.

**F.4 — The `--checkout` flag exists for the two-checkout case.**
Ask 43's realistic failure is "I edited `~/Elaria` but `~/.config/systemd/user/
assistant.service` still points at `~/Elaria-old`". `--checkout PATH` compares a
named tree against the running daemon, so that case is one command rather than
two shells.

**G.1 — `file_leg_probe.py` is NOT rebuilt, and this is now a measurement.**
Round 1 said it was absent; this round checked whether it *could* be built. It
cannot, honestly: it imports `asr.batch_chain` and `asr.configured_languages`
(present) but calls `batch_transcription_prompt` and `extract_transcript` from

non-trivial dependencies are missing, so writing it here would mean inventing
behaviour for symbols I cannot read. It stays owed, with the reason named:
`file_leg_probe.py` belongs on the tree that has A's voice chain, not on this one.

**G.2 — My first implementation of the pid proof could never have worked, and the
number that exposed it was `daemon_pid -1` with a live daemon.** Two separate bugs:

  * `os.stat(socket).st_ino` was compared to `/proc/<pid>/fd` entries. A UNIX
    socket's *filesystem* inode and its *kernel* socket inode are different
    numbers from different tables; they can never be equal. Fixed by reading
    `/proc/net/unix`. Pinned by `test_a_filesystem_inode_is_not_a_socket_inode`.
  * The rewritten parser skipped any row whose first column ended in `:`. But
    **every data row's first column is a kernel pointer ending in `:`** — so the
    header skip dropped the entire table and the probe reported "socket not
    bound" while the socket was demonstrably bound. Fixed; pinned by
    `test_data_rows_start_with_a_colon_and_must_not_be_skipped_as_headers`.

Both were found only because a real daemon was started and the real readback run.
A mocked `/proc` would have agreed with either bug.

**G.3 — `stale_source_files` printed `0` with no daemon in the first draft.**
That reads as "nothing stale" about a comparison that never happened. Now `-1`,
matching the limiter reader's three-valued rule. Pinned.

**G.4 — What an empty result fails to discriminate (ask 43 specifically).** A
`daemon_down` readback cannot tell apart: no daemon configured / the unit failed
to start / the socket lives in a different `XDG_RUNTIME_DIR` / the daemon died
after binding. More importantly it says **nothing** about whether the checkout is
stale, because there is no process to compare against. The script prints that on
every `daemon_down` run.

**G.5 — The live verification left no trace in the tree.** The daemon ran on
`/tmp` XDG dirs with its own sqlite file, was stopped, and the dirs removed. The
`touch` that proved `stale_checkout` changed a tracked file's **mtime only** —
`git status` is clean for it (content unchanged, no diff), confirmed before commit.
