# RPT-O-r2 — hands last mile: real key emission in `UinputTypeSink`

**Scope: SANDBOX / TESTED-ONLY. NO HARDWARE CLAIM.** Branch
`arena/0a32edfe-elaria`, from `a0a4e3c` (main). PR #98 built the gate but its
`UinputTypeSink` always refused. This round implements key emission in that
sink and nowhere else.

## What changed

- `src/assistant/hands/runner.py`: `UinputTypeSink` now emits evdev `EV_KEY`
  press/release pairs with one `SYN` after each state change, from a complete
  printable-ASCII → Linux key-name map (US layout). Shift is held only across
  the upper form of a key; no control/meta chords, no Enter/Tab/Backspace.
  Non-ASCII printable input and control bytes are refused, never guessed.
- `evdev` is imported **lazily** via `importlib.import_module`, only inside
  emission. `UinputTypeSink(..., evdev_factory=...)` is a keyword-only trusted
  hook returning an evdev-like module (`ecodes` + `UInput`); it is never read
  from config, plans, data or env. No factory: the original preconditions are
  unchanged (`disabled-by-config`, `evdev-absent`, `uinput-absent`).
- **No readback is faked.** `has_readback` stays `False`, `last_typed()` stays
  `None`, and nothing caches the typed text as proof. `SandboxCore` is
  untouched: it still refuses the real sink before `type_text`, so a real
  keystroke is never marked verified. Every sink refusal is logged at WARNING
  with its reason (and the core still logs a `hands.step` refusal row).
- `src/assistant/hands/README.md`: documents the emission shape, injectable
  factory, US-layout limit, and the unverifiable-readback boundary.
- `tests/test_o_uinput_emission.py`: 9 new sandbox tests, including the
  eye-check `test_eye_check_fake_evdev_open_gate_emits_exact_keys_closed_gate_emits_none`.
