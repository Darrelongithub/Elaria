## WHAT WAS BUILT — the wiring, and only the wiring

`_hotword_loop` now keeps `feed()`'s return value and hands it to
`_wake_listen_after_feed`, which applies the five rules in order and returns
early at every one:

1. **Only a verified ATTENDING result opens listening.** `_is_verified_attending`
   demands four independent agreements on the verdict record the guard already
   writes: `outcome == "attending"`, `confidence == "high"`, a real
   `ecapa_score`, and not the `--unsafe-energy-test` plumbing flag — plus the
   guard's own state must be `attending`. Uncertain, unverified, short,
   replayed, energy-test, unavailable scorer, unconfigured guard, and any
   exception from `feed()` or from `open_listening()` all take the same exit:
   no session, no state change, no reply.
2. **The session is bounded.** Three bounds, all enforced:
   an audio-time hard ceiling of **60 s** (`WAKE_LISTEN_CEILING_S`, a code
   constant the reader cannot be talked out of), the guard's own
   `SilenceLadder` silent close — the same ladder object dictation uses — with
   its window clamped to **12 s** (`WAKE_LISTEN_WINDOW_S`) because the shipped
   `[hotword] checkin_after_s` is a dictation-shaped 30 s and this path
   transcribes nothing, and a stop event fired by `hotword.stop` or daemon
   close. The frame queue is bounded (32), so a reader that falls behind closes
   the session instead of buffering a microphone.
3. **Half-duplex is inherited, not raced.** The session does **not** open a
   second capture: it reads the frames the always-on loop already owns
   (`_WakeFrameSource`), and the loop bypasses the ring-pending path while a
   session is live. A busy mic — `is_speaking()` (`_MutedCapture` holds the
   gate) or PTT live/transcribing — drops the session silently: zero sessions,
   zero outbound bytes, no `capture.state`. Checked again on every frame, so a
   mic taken mid-session closes it.
4. **`capture.state` on every transition.** A verified hit emits
   `verifying` then `open` (exactly once each, in that order). Every close
   goes through the guard's own `endpoint_closed()` — the same close dictation
   uses, which also zeroes the ring/pending/head — and emits `armed` (path
   still armed) or `released`. A rejected hit emits **nothing at all**: the
   suite proves this by diffing the state stream of a rejected hit against the
   same stream with no hit whatsoever.
5. **No model, no session.** An unavailable scorer, an empty
   `[hotword] keyword_model`, or a guard exception means no session, no state
   change, no reply, zero outbound bytes.

Everything lives in `daemon.py`, which `OWNERS.yaml` assigns to Z. My first
draft also touched `wake_guard.py` (J) and `config.toml.example` (L); the
ownership check showed that immediately, so I moved that logic into the daemon
instead of borrowing another lane's files.

## HONEST SCOPE / NOT PROVEN

- **No hardware, no microphone, no PipeWire.** Every frame is synthetic or a
  file read through the real pinned model. Nothing here is a hardware claim;
  the mic could still be unavailable on the owner's laptop, and that path
  correctly reports `unavailable`.
- **The session transcribes nothing.** Wiring a verified hit to listening is
  this lane; turning what is heard into a turn is not. The session therefore
  cannot earn a ladder check-in (`heard_speech` stays false — no words land),
  which is why its close is silent and why the window is clamped to 12 s: 12 s
  of capture, then a silent close, then idle. That is bounded and honest, but
  it is not a conversation.
- **The 12 s window is a judgement, not a measurement.** Dedicated dictation
  has a transcript to justify waiting 20–30 s; this path has none, so I cut it.
  If the next lane adds transcription, this constant should be revisited with
  real data.
- **`_WakeFrameSource` queue depth 32 (≈1 s)** is sized for a runner that only
  runs energy/endpoint checks. A slower consumer will close sessions early —
  by design, but it will look like short sessions if one is ever wired in.
- **The replay guard is exact-byte.** Re-running the same clip twice is
  refused (correctly, and it bit my own first draft of the tests).
- **`wake_guard.py` still returns its verdict without a `verified` bit.** I
  derive verification from the `TriggerRecord` it already writes instead of
  asking J's file to carry a new field. That is a deliberate ownership
  trade-off, recorded here so J can add the bit if that is preferred.
