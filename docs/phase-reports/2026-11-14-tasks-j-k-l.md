### J — EARS (`7d0d3ca`)

  `capture.py`'s existing energy gating — no new dependency).
- Local faster-whisper is the dictation PRIMARY at tier `base`, chosen and
  measured; escalation to the Gemini batch chain happens only below 0.65 local
  confidence and is labelled `double-pass` **only when the local leg produced
  words** (otherwise `path="escalation"`, `labelled=None`).
- Per-path provenance on every transcript: backend, model, latency_ms, audio_s,

  no lookahead, per-chunk, allocation-free, applied before VAD/ASR/live.

### K — GATEWAY (`b38b1b1`)

- New `src/assistant/audio_gateway.py`: `AudioGateway`, `GatewayRefused`,
  `Arbitration`; states `idle/ptt/live/speaking`; bounded transition log.
- F17: node policy is explicit param → `[capture] mic_target` →
  `[meeting] mic_target`. On a machine that CAN open a device an unnamed node
  is a REFUSAL, never the system default. Where no device can be opened at all
  (no `pw-record`: containers, CI, fake-device pins) the question does not
  arise, and the pre-existing no-device fallback answers with its reason
  logged. Device failures are a separate refusal kind, so the daemon's
  simulated fallback can never swallow a policy refusal into "pretend audio".
- The policy check runs **before** the session-open earcon: a deployment that
  cannot name its node never gets a beep promising a listener.
- F28: PTT is inert during a live session; a live session is suppressed while
  PTT holds the mic; pressing the key during playback is allowed (that is how
  the owner interrupts her). A second press while already listening stays the
  daemon's own `already listening` case so a finished session can be
  superseded instead of deadlocking.
- F28 one-reply: `claim_reply(session_id)`, first caller wins, bounded to
  exactly 256 ids with oldest-first forgetting — see DEFECTS FOUND for what is
  and is not wired.
- F16: whole-reply playback only, tracked by the gateway; streaming playback
  is named deferred in `status()`, never promised.
- F30: cancel and release are answered by the gateway that owns the session,
  and the cancel count is in `status()`.
- Daemon: `self.audio = AudioGateway(...)`; PTT capture, ack playback and
  `_speak_once` playback all go through it; `is_speaking` now also reports the
  gateway's playback set so the half-duplex gate and the gateway cannot
  disagree; `status` carries a `gateway` snapshot.
- The capture-class seam resolves at call time, so BOTH existing fake-device
  habits (`assistant.daemon.PipeWireCapture`, `assistant.capture.PipeWireCapture`)
  still describe what a session would really have opened.
- `live_client.py` untouched (PROTECTED): the live conversation stream keeps
  its own path until a quoted grant migrates it.

## DEFECTS FOUND

Everything here is out of the named scope; none of it was fixed silently.

1. **The gateway's `claim_reply` is landed and pinned but not on the live reply
   path.** F28's "one utterance never yields two replies" is today enforced by
   the daemon's existing single-claim (`_early_reply_tasks` pop, `_claim_early_reply`)
   — which the early dispatch and the late gate already share. Wiring a second
   authority over the same invariant risked a desync, so the gateway rule
   stands ready for the next reply consumer rather than duplicating the live
   one. If the owner wants the gateway to be the sole authority, that is a
   small, quotable follow-up.
2. **Three capture paths remain outside the gateway**, deliberately: the
   always-on hotword capture (`_hotword_capture_factory`), `event.py`'s event
   capture, and `_meeting_start`'s dual-channel capture. None is PTT/dictation;
   migrating them needs its own grant, and the meeting path's dual-source
   semantics (mic + system) do not map onto a single-owner gateway yet.
3. **`live_client.py` keeps its own live audio stream** (PROTECTED). The
   gateway's F16 playback covers whole replies only; the live conversation
   stream is untouched and still owns its own uplink/downlink.
4. **F17's refusal is device-conditional.** Where no device can be opened at
   all (no `pw-record`), an unconfigured node does not refuse — otherwise every
   headless/CI run and every fake-device pin would have to fabricate a node.
   On the owner's laptop (`pw-record` present) an unconfigured node refuses
   before any sound. This is stated because it is a judgement call, not a
   reading of the rule.
5. **The daemon's `is_speaking` is now the union of two registries** (its own
   playback sets and the gateway's). That is intentional honesty for the
   half-duplex gate, but it does mean one playback task registered twice would
   keep the gate shut for its own duration — no such double registration exists
   today (both call sites register a single task).
6. **`[tts] cache_max_files = 120` is a guessed default**, declared and
   documented but not measured against the owner's real usage.
