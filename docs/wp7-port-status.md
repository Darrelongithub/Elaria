# WP7 port: current safety and validation status

**Do not treat this port as live-approved.** It has been exercised only with synthetic local files and fake restic/rclone binaries. The owner's live-traffic, go/no-go, stop-condition, privacy and merge holds remain in force. Existing owner packets from the earlier branch do not describe this port and must not be used as live instructions.

The implementation now requires an explicit absolute `--artifact` for a non-dry-run backup. It considers only the dedicated audio directory, refuses unless the selected WAV is the sole cold candidate, checks free space and the capacity floor before uploading, and serializes CLI runs. It writes a local manifest entry, invokes restic for that one file, records the returned snapshot ID, restores and hash-checks that snapshot, then records a flip and moves the local file to grace trash. No automatic purge is configured. An upload or verification failure leaves the local file in place. Fetch refuses to overwrite an existing destination and verifies a pinned snapshot before publishing it.

`backup status` is a manifest summary, **not a discovery census**. `backup run --dry-run` is a path-free classification, not evidence of upload. An empty drill and a missing restic check are not passes. A file already distorted before backup should sound the same after restore; hash equality, not subjective sound quality, is the integrity criterion.

The code needs an existing restic repository and locally configured rclone remote and private credential files. No repository initialization, credentials, real audio, or MEGA traffic was used to test it. The port deliberately does not install or enable unattended timers; the earlier timer design did not supply the newly required explicit artifact and would not satisfy the single-artifact live authorization. Recovery after a process dies between moving a file and recording the trash location still requires owner investigation; no automatic deletion is authorized.
