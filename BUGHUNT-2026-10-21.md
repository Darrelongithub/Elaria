# Elaria bug hunt — 2026-10-21 (branch `arena/dca11d17-elaria`)

Method: reproduce first (failing `test_bug*` regression), fix at the root,
`bugs.md` entry (BH-K series). Baseline at `402297f`: **1417 passed, 6 skipped**
(1423 collected), ruff clean. Severity order: silent data loss/substitution >
unbounded waits > authority/privacy leaks > crashes > wrong output > cosmetic.

SDK ground truth established in-sandbox (google-genai 2.32.0 introspection):
every duck-typed attribute `GenaiLiveTransport` reads exists on the real types
(`input_transcription`, `interim_input_transcription`, `finished`,
`turn_complete`, `session_resumption_update{resumable,new_handle}`, …);
`files.upload(file=…)`, `client.voices`, both `LiveConnectConfig` shapes and
`send_client_content(turns=dict)` all construct. The hardware Live failure is
therefore protocol/state logic in this repo, not SDK-shape drift.

## Confirmed bugs (fix list, severity order)

### Silent data loss / substitution
- **BH-K1** `transcribe.dictate`: a post-persist FILLER_PHRASES substring check
  replaces the returned SessionResult with an empty one (raw/cleaned/inbox/
  clipboard/transcript_id all falsified) after the transcript was already
  stored. Dictating "…let me know how I can help…" returns nothing.
- **BH-K2** `daemon._is_echo` + `_finish_dictation`: any transcript that merely
  *finishes* while an ack is playing (or contains a filler phrase) is judged
  "echo" and wiped from `ptt.result` — no comparison against what she said.
- **BH-K3** Live final-after-activity_end (hardware-confirmed), root cause:
  (a) `GenaiLiveTransport` swallows the server's `turn_complete` for the
  transcription-only model, so when all segments committed during speech there
  is no post-release terminal; (b) `dictate` then marks `live_terminal_missing`
  and the saved-WAV **batch result overwrites good Live finals**. Every
  dictation double-transcribes; the Live text is silently substituted.
- **BH-K4** `GEMINI_MODE=record` never records Live sequences
  (`RecordingTransport` unwired in `make_live_transport`) — the documented
  debugging path for exactly BH-K3 produces no fixture.

### Unbounded waits / hangs
- **BH-K5** `gemini_client._run_coroutine_sync`: `thread.join()` with no
  timeout around a Live render whose `receive()` can wait forever.
- **BH-K6** `PipeWireCapture.aclose()`: `await proc.wait()` after SIGTERM with
  no kill escalation; caller-side cancellation abandons the wait and can leave
  pw-record running.
- **BH-K7** Hotword capture leak: `_hotword_loop` finally calls sync `close()`
  (does not exist on `PipeWireCapture`) — pw-record survives `hotword stop`;
  watchdog `check()` only runs on frame arrival; capture-stall stream-end exits
  the loop without disarm/"stalled". Orphaned live microphone.
- **BH-K8** CLI `plan build` polls `plan.show` forever if a plan row is stuck
  in `building` (daemon died mid-build).
- **BH-K9** `KnockSignal.emit` runs `subprocess.run` (≤5s ×2) on the daemon
  event loop inside knock handlers, and plays the knock sound outside the
  speaking/duplex gate.

### Authority / privacy
- **BH-K10** `wake_guard._in_class_mode()` / `_guest_door_blocked()` return
  False on exception — fail OPEN: a broken presence/showoff read lets a wake
  accept open voice listening in class mode / during show-off.
- **BH-K11** `DisclosureService.company()` caches per-process forever; the
  daemon never observes company state written by another process (CLI local
  path). `PresenceService` reads fresh — disclosure must too.

### Error surfacing / wrong output / crashes
- **BH-K12** CLI treats daemon error replies (ipc `RuntimeError`) as "daemon
  unavailable" and re-runs operations against the local store: refusals are
  masked and state splits. E.g. `assist review approve 999` prints
  "item 999: approved", exit 0, nothing happened (`set_item_decision` result
  ignored on the local path). Fix: distinct `ipc.DaemonError`; fallbacks only
  on `DaemonUnavailable`.
- **BH-K13** `parse_wpctl_status` merges the Video group's second `Sources:`
  section into audio Sources and attributes Streams/Devices/Default-Configured
  entries to the last matched section — cameras/streams offered as mic nodes.
- **BH-K14** Event subscribers leak (observed: 2): `ipc.serve` never notifies
  the daemon on disconnect; pruning waits for the next broadcast to fail.
- **BH-K15** Executor has no cross-process lock: daemon `plan.apply`
  (to_thread) racing a CLI local apply double-spends the hourly cap and can
  double-apply a plan. Fix: non-blocking flock, clear refusal.
- **BH-K16** `Executor.trash()` writes the manifest + reports `trashed_as`
  even when the journaled move failed; same-second same-name trash collides.
- **BH-K17** `Executor.undo` of a `copied` op whose both copies exist fails
  with a misleading FileExistsError instead of reconciling the duplicate.
- **BH-K18** Quota: per-model RPD in `[quota.models.*]` is never enforced (only
  a global 1200/day), and the RPM limiter reads only the flat keys — two
  sources of truth for the same limits.
- **BH-K19** `[asr] assert_output_language` is never called; the local Whisper
  backend discards faster-whisper's detected language and reports the pinned
  one, so silent translation is undetectable at the tag level.
- **BH-K20** Config keys read but undeclared: `[organise] tier1_batch_size`,
  `tier2_batch_size`; `[hotword] sample_rate`, `unit_path` — doctor reports
  "unknown key" for keys the code honours.
- **BH-K21** `meeting.start` ignores `[capture] mic_target` (dictate/hotword
  resolve capture→meeting; meeting resolves meeting-only).
- **BH-K22** Store: no WAL / `busy_timeout` — cross-process writers (daemon +
  CLI fallback + doctor) can fail instantly with "database is locked".
- **BH-K23** Keyword model is scored per single 30 ms frame; a stateless
  phrase model can never trigger (the energy test double can — classic mock
  fidelity gap). Score the pre-wake ring window instead.
- **BH-K24** Malformed `config.toml` → raw traceback from `load_config()` in
  every CLI invocation (loaded before the try).
- **BH-K25** `tts.play_audio` uses a fixed 120 s player timeout while the ack
  path holds the mic gate for the player's lifetime — a wedged player mutes
  capture for up to 2 minutes. Timeout should derive from WAV duration.
- **BH-K26** Doctor systemd drift check covers only `assistant.service`;
  `elaria-console.service` / `elaria-overlay.service` are also copy-deployed.

## Suspects (evidence noted, not provable in the sandbox)

- **S1** Live model ids (`gemini-3.5-transcribe-live`, `gemini-3.8-live`)
  exist for the owner's key — settle: `assist voice models`.
- **S2** Exact server ordering of the final committed segment vs
  `turn_complete` after `activityEnd` — settle: `GEMINI_MODE=record` dictate,
  inspect `fixtures/seq-live.jsonl` (works after BH-K4).
- **S3** `_SdkTransport.generate_audio` fallback `send_realtime_input(text=…)`
  may not end the turn on the real API (primary `send_client_content` path is
  signature-verified) — settle: `assist voice say "test"` on hardware.
- **S4** `ipc.subscribe_events` has no read timeout (BH-H6 once claimed 30 s;
  absent now) — a wedged-but-alive daemon freezes Waybar/console feeds.
- **S5** `no_speech` verdict (`peak frame RMS < 0.003`) can discard a real
  transcript of very quiet speech. Settle: `assist doctor` mic-level check +
  one quiet dictation, compare `capture.stats`.
- **S6** `DuplexLiveTransport` drops a genuine user `final` that arrives
  inside the 400 ms output guard.
- **S7** Hotword `feed()`/`verify()` run synchronously on the daemon event
  loop (onnx inference + ECAPA subprocess) — ack latency risk on hardware.
- **S8** `_sdk_transcribe` never deletes the Files-API upload (retained
  server-side until expiry). Settle: Files list after a batch transcription.
- **S9** `meeting.stop` awaits `transcribe_dual` in a thread with no overall
  bound (per-segment whisper.cpp timeout alone is 900 s); `_meeting_processing`
  would park mode switches until it returns.
- **S10** CLI local `knock accept` on a wake-knock (daemon down) bypasses
  `WakeGuard` entirely; nothing reconciles it on daemon restart.
